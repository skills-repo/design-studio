# 界面审查

> 审查界面的一致性和可用性，发现布局问题、交互缺陷和视觉层次混乱。

## 能力

- **布局审查**：对齐、间距一致性、响应式断点问题
- **视觉层次**：字号层级、颜色对比、信息优先级
- **交互一致性**：按钮/链接/表单的行为一致性
- **状态覆盖**：loading/empty/error/edge case 状态检查
- **改进建议**：每个问题附带具体的 CSS/代码修改建议

## 使用方式

在 Claude Code 中使用 `/ui-review` 调用。

```
/ui-review 审查登录页面的 UI 一致性
/ui-review 检查整个应用的按钮样式是否统一
```

## 工作流

1. 提供页面截图、URL 或组件代码
2. AI 逐区域分析布局、颜色、间距、交互
3. 列出问题清单（严重/一般/建议三级）
4. 对每个问题给出修复代码
5. 输出审查报告

## 输出格式

```markdown
## UI 审查报告

| # | 问题 | 位置 | 严重度 | 修复 |
|---|------|------|--------|------|
| 1 | 主按钮和次按钮颜色太接近 | nav.tsx | 严重 | 调整色相差≥30° |
| 2 | 移动端卡片间距不一致 | card.tsx | 一般 | 统一使用 16px gap |
```

## 适用场景

- PR 中前端改动的 UI 审查
- 上线前的视觉走查
- 设计稿与实现的一致性验证
- 独立开发者自检（没有设计师审查）

## 限制

- 不审查品牌调性和情感设计
- 复杂动画的流畅度需要人工体验
- 移动端需要提供多尺寸截图
